## Contribution Layers (φ-weighted)

### Layer 1: Core Contributors (φ² = 2.618)
Direct ecosystem developers with merge authority and architectural decisions.
- Full context tracking
- Session history
- Communication preferences
- Decision patterns

**Examples:** zeyxx, sollama58

### Layer 2: Active Contributors (φ = 1.618)
Learning developers, community builders, those actively working on ecosystem.
Even if nothing in production yet - **intention matters**.
- Contribution tracking
- Learning patterns
- Growth trajectory

**Examples:** ragnar-no-sleep

### Layer 3: Dependency Developers (1.0)
Developers of tools the ecosystem depends on.
They contribute **malgré eux** (despite themselves).
- Commit history from forks
- Code patterns
- Implicit knowledge transfer

**Examples:** Alex Newman (claude-mem), dependency maintainers

### Layer 4: Infrastructure Providers (φ⁻¹ = 0.618)
Companies/developers providing critical infrastructure.
Their code runs every transaction.
- API patterns
- SDK knowledge
- Integration documentation

**Examples:**
- Helius RPC engineers
- Jupiter aggregation team
- Solana core developers

### Layer 5: Foundation Layer (φ⁻² = 0.382)
The bedrock upon which everything is built.
Ultimate source of capabilities.
- Model understanding
- SDK patterns
- Safety principles

**Examples:**
- Anthropic engineers (Claude)
- OpenAI (if used)
- Node.js maintainers

## E-Score Attribution

Every layer earns E-Score proportionally:

```
E_layer = contribution_value × φ_weight × time_decay
```

This means:
- Alex Newman earns E-Score for claude-mem commits
- Helius engineers earn E-Score for RPC reliability
- Anthropic engineers earn E-Score for Claude capabilities

## Security by Design

### Privacy Tiers
- **L1-L2**: Full tracking with consent (ecosystem members)
- **L3-L5**: Aggregated/anonymized (public commits only)

### Identity Protection
- Hash-based operator IDs for privacy
- No PII storage for external contributors
- Public git data only
